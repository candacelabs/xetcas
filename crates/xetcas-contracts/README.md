# xetcas-contracts

Wire-exact Rust types and boundary validators for the Xet CAS v1 contracts.

The protobuf schemas in [`../../proto/xetcas/v1/`](../../proto/xetcas/v1) are
the source of truth. This crate is what a Rust server links against:

- **`v1`** — message types generated from those schemas by
  `cargo xtask gen-proto` and committed at `src/generated/candace.xetcas.v1.rs`.
  Their serde attributes make JSON serialization byte-compatible with the real
  `xet-core` client; every attribute is configured (and justified) in
  [`../../xtask/src/main.rs`](../../xtask/src/main.rs). **Never hand-edit the
  generated file.**
- **`v1::validate`** — one `validate_*` function per message that carries
  rules: each Liquid Proto `expr` from the schema, plus the cross-field
  invariants (range ordering, parallel array lengths, derived totals) that a
  single-field predicate cannot state.
- **`constants`** — the fixed protocol strings and limits: the `default`
  prefix, the `X-Xet-*` batch-action headers, the Git LFS content type and
  transfer names, and the xorb/chunk size limits.

The Go twin of the same schemas lives in [`../../go/xetcasv1`](../../go/xetcasv1),
generated by `proto/generate.sh` with `protoc-gen-liquidproto`; its `Validate*`
functions and this crate's `validate_*` functions must stay in agreement.

## Working on it

```bash
cargo xtask gen-proto           # regenerate src/generated/ after a .proto edit
cargo xtask gen-proto --check   # fail if the committed output has drifted
cargo test                      # golden JSON, upstream parity, validator tables
```

Tests are the real specification of the wire format here: `tests/` compares
serialized bodies against the OpenAPI examples and round-trips them through the
published `xet-client` 1.6.0 types.
